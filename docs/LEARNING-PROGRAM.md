# A reusable learning process

The objective is to improve S3, BW and PCC into a system that observes a failure,
creates a verified lesson, trains a candidate, measures learning and forgetting,
and accepts or rejects that change with reproducible evidence. Wen is the model
helping build this machinery for Codi. Wen and Codi are separate models.

## Responsibilities

- S3 owns the skill graph, independent checks, practice selection, retention and
  research reports. It stays usable without importing BW or PCC.
- BW owns tasks, tool grants, actual execution and the original task ledger.
- PCC owns inference, native backprop, model identities, GPU leases and candidates.

Keep these boundaries. A study driver uses the existing components; it does not
introduce another workflow engine or allow a model to approve its own update.

| Repeat and explain | Pinned sources, owned practice TXT, commands, original outcomes, resource cost and a human-readable conclusion | Existing guides and private receipts; unified campaign accounting and teaching report remain to complete |

A generated fixture or injected regression proves machinery, not model quality.
A planned graph node is unmeasured. A retained small score does not establish
preservation of code, administration, writing or other untested domains.

## Experiment progression

1. Audit failure categories and actual selected targets. Qualify full updates on
   the current model with ordinary backprop and saved-candidate reload.
2. Measure learning on a small verified practice set. Compare update settings,
   adapter capacity and direct full tuning with explicit independent candidates.
3. Compare repetition, varied questions and independently checked demonstrations.
   Record both training occurrences and selected target tokens.
4. Interleave review. On a regression, retain its original evidence, use separate
   practice examples to address the affected skill, and preserve all test gates.
5. Use short coverage checks at checkpoints, extended per-domain checks at
   milestones and sealed final checks for a selected recipe. No claim extends
   beyond tested domains, profiles and difficulty cells.
6. Record an understandable learning curve and the next falsifiable question.

The current owner has approved one fixed-seed campaign; repeated runs with other
seeds are outside this campaign. Report uncertainty and limited replication.
RoPE/YaRN/position-extension research is included as a measured extension branch;
model metadata, configuration, memory, numerical agreement and quality must be
checked. Existing Wen 128K maximum/96K compaction policy remains the baseline
until a separately identified extension is measured. Neither a position-setting
change nor a tiny-model long-context test proves long-context Wen capability.

## Frozen acceptance policy

The revision-2 guard detaches input data and verifies the entire tree, its
indices and guard settings before work and after external callbacks. A changed
threshold, practice pool, checker or evaluator contract cannot retain the old
policy identity. Changing source or policy requires a deliberate new baseline;
a previously qualified hat does not silently continue under a different policy.

The [policy evidence](../validation/learning-program-20261024/frozen-policy.json)
records a reproduced acceptance bug, its repair, 82 core tests, 14 actual PCC
controller tests and four native CPU updates through BW/PCC. Semantic scores in
that CPU integration are controlled injections and remain labeled as such.

## Operator entry points

Start with [the handoff](OPERATOR-HANDOFF.md),
[the native pilot guide](FOUNDATION-TRAINING-PILOT.md), and the actual owner's
private machine authorization. Use new private output directories; inspect and
reconcile existing operations instead of repeating uncertain updates.

Each study report must state the hypothesis, one intended change, comparison,
counts and denominators, actual GPU allocation-hours, original failures,
acceptance/rejection, limits and next experiment. Publish reviewed code and
aggregate results incrementally. Generated GGUFs remain on the training host
for this campaign; reports identify them by hash rather than uploading weights.
